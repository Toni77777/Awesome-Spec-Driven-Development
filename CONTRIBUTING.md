# Contributing

Thanks for helping improve **Awesome Spec-Driven Development**! Contributions are welcome via pull request or issue.

## What belongs here

Add a tool or resource only if it fits one of the existing sections:

- **Core SDD Frameworks**: a written specification is the central, durable artifact that feeds plans, tasks, and implementation.
- **Adjacent Layers**: commonly grouped with SDD (context engineering, skills/methodology enforcement, orchestration) but not a spec format itself.
- **Articles, Comparisons & Research**: guides, comparisons, and papers about SDD.

## Requirements

- The project must be **open source** and actively maintained (recent commits or releases).
- It must be **free to use**. Paid-only products are not accepted.
- It must be genuinely about spec-driven development, not just "AI coding" in general.
- Links must work, and star counts (if given) must be current.
- No duplicates. Search the list before adding.

## Format

Add one line per entry, in this format:

```markdown
- **[Name](https://github.com/owner/repo)** — ~1.2k ⭐. One or two sentences on what it does and why it matters.
```

For articles:

```markdown
- **[Title](https://example.com/article)** — One-line description.
```

Guidelines:

- Keep descriptions factual and neutral. No marketing language.
- Say which layer the tool belongs to (Core or Adjacent) in your pull request.
- Keep entries in the right section; within a section, newer or more relevant items go last.
- Use sentence case and end descriptions with a period.

## Pull request checklist

- [ ] The entry is in the correct section and follows the format above.
- [ ] The link works and the description is accurate.
- [ ] The tool is open source and free.
- [ ] The PR title is `Add <name>` (or `Remove <name>` / `Update <name>`).

## Removing or updating entries

If a project is archived, renamed, or no longer fits the scope, open an issue or a pull request to update or remove it.
